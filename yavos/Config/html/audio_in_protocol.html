Audio Input Bus Protocol

Devices which wish to provide audio data into the system must be able to connect to a web socket server and communicate binary data. The audio input bus recognizes four types of binary input.
  • WEB - webm data. typically produced by browsers
  • WAV - wav data. any format will be fine
  • MP3 - mp3 audio data
  • MP4 - mp4 video data

The binary data format is communicated from the smart microphone to the audio input bus in the initial data exchange between the smart microphone and the audio input server as described below. Note smart microphones do not provide speech recognition. This is done on the YAVOS system. Smart microphones must provide silence detection. This is typically done using webrtcvad but simple alternatives are also suitable.

Message Delimiters

Messages start with a 7 byte sequence and end with a 7 byte sequence. In between binary data is sent. Chunking may be required if audio data is too long for single web socket packets.
  • BIN WEB - webm data follows.
  • BIN WAV - wav data follows
  • BIN MP3 - mp3 audio data follows
  • BIN MP4 - mp4 video data follows
  • YaENDvO - end of the binary data stream


Smart Microphone Operation

A smart microphone first connects to the audio input bus and then begins detecting human speech. Once the smart microphone detects a human utterance it first sends a 7 bye sequence to notify the audio input processor that it is about to send it binary data. This 7 byte sequence must be the string 'BIN XXX' where XXX is one of WEB, WAV, MP3, or MP4 indicating the type of data it is sending.

Once the binary data has been sent the smart microphone must send another 7 byte string indicating the binary data transfer is complete. This 7 byte string is always YaENDvO. It must be this exact 7 byte string and it is case sensitive. Failure to provide this string in this exact format will cause a synchronization error on the audio input bus for this connection.
